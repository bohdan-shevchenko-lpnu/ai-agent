
# Архітектура AI-агента

## 1. Призначення агента

AI-агент призначений для автоматизації типових етапів розробки програмного забезпечення: створення структури проєкту, підготовки вихідного коду, налаштування складання, тестування та безперервної інтеграції.

Агент повинен зменшувати кількість ручних повторюваних операцій, забезпечувати послідовність виконання завдань і допомагати виявляти помилки до завершення роботи.

У межах лабораторної роботи агент створює кросплатформний проєкт Hello World мовою JavaScript, використовує npm scripts для запуску та перевірки програми, Jest для модульного тестування й GitHub Actions для автоматичних перевірок.

## 2. Основні компоненти

### 2.1. Маніфест агента

Маніфест `build-engineer.agent.md` визначає роль агента, його відповідальність, правила роботи з файлами, обмеження, заборонені дії та критерії успішного завершення.

### 2.2. Skills

Агент використовує три основні skills:

- **project-scaffold** — створення структури JavaScript-проєкту, вихідних файлів і початкової конфігурації.
- **build-and-test** — налаштування npm scripts, залежностей і модульних тестів Jest.
- **github-actions** — створення GitHub Actions workflow для автоматичного складання та тестування на Windows, Linux і macOS.

Skills містять інструкції, які визначають порядок виконання відповідного типу завдання та очікуваний результат.

### 2.3. Prompts і команди

Для запуску окремих операцій передбачаються такі prompt-файли:

- `git-init.prompt.md` — ініціалізація Git-репозиторію та підготовка його структури.
- `create-project.prompt.md` — створення проєкту Hello World.
- `create-build.prompt.md` — налаштування складання та тестування.
- `create-actions.prompt.md` — створення GitHub Actions workflow.
- `check.prompt.md` — перевірка структури, складання та тестів.
- `init.prompt.md` — запуск повного сценарію автоматизації.

Ці файли задають інструкції для Copilot. Фактичний спосіб виклику кожного prompt залежить від підтримки відповідного формату в середовищі VS Code.

### 2.4. Оркестратор

Оркестратор координує повний сценарій: перевіряє початковий стан репозиторію, визначає послідовність операцій, ініціює потрібні етапи, перевіряє результати й формує підсумковий звіт.

Повний сценарій повинен охоплювати створення проєкту, налаштування складання і тестування, конфігурацію GitHub Actions та перевірку результату.

## 3. Дані між етапами

Між етапами передаються такі дані:

1. Початковий стан репозиторію: наявні каталоги, файли та конфігурації.
2. Параметри проєкту: мова JavaScript, структура каталогів, npm scripts і спосіб тестування через Jest.
3. Результати створення проєкту: вихідний код, `package.json`, тести та lock-файл залежностей.
4. Результати налаштування CI: файл `.github/workflows/ci.yml` з матрицею операційних систем.
5. Результати перевірки: коди завершення команд, повідомлення про помилки, результати складання та тестів.
6. Підсумковий звіт: перелік створених файлів, виконаних перевірок і невирішених проблем.

Секрети, паролі та токени не повинні передаватися в документацію або записуватися до журналів.

## 4. Обробка помилок

Оркестратор повинен перевіряти результат кожного етапу перед переходом до наступного.

Якщо команда завершується помилкою, агент повинен:

1. Визначити, на якому етапі виникла проблема.
2. Зібрати доступні повідомлення про помилку.
3. Встановити можливу причину та запропонувати або виконати безпечне виправлення.
4. Повторити відповідну перевірку.
5. Зупинити сценарій, якщо помилку не вдалося усунути.
6. Включити інформацію про помилку до підсумкового звіту.

Агент не повинен повідомляти про успішне складання, тестування або виконання GitHub Actions без фактичного підтвердження результату.

## 5. Правила роботи з файлами та безпека

Агент повинен працювати в межах поточного репозиторію, перевіряти наявні файли перед змінами та не перезаписувати сторонні дані без потреби.

До Git потрібно додавати вихідний код, тести, конфігурації, інструкції агента й документацію. Каталоги залежностей, кеші, тимчасові результати та секрети потрібно виключати за допомогою `.gitignore`.

Агент не повинен розкривати токени, паролі або приватні ключі, видаляти сторонні файли чи виконувати небезпечні Git-операції без дозволу користувача.

## 6. Критерії успішного завершення

Робота агента вважається успішною, якщо:

- створено JavaScript-проєкт Hello World;
- налаштовано npm scripts;
- модульні тести Jest проходять;
- створено GitHub Actions workflow для Windows, Linux і macOS;
- результати локальних перевірок задокументовано;
- створено інструкції запуску агента та програми;
- у підсумковому звіті наведено фактичні результати й відомі проблеми.

Успішний локальний запуск не замінює перевірку GitHub Actions на GitHub.
